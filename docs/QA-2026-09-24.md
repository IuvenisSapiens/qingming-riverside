# 2026-09-24 发布检查

本次同时检查主长卷、孙羊正店和中秋灯市。测试在本机浏览器与触屏模拟环境执行，未使用实体手机；性能数字不代表所有手机或网络。

## 修复

- 手机食单显式使用横向布局，清除旧样式继承的纵向排列；可横滑选到全部九道菜。
- 食单中的画师保持在视口内，短横屏将食单上移，备餐按钮保持可见。
- 从酒楼返回长卷后，直接回到茶市酒楼外，而不是重新选景。
- 访问计数移到控制图标旁，避免遮挡窄屏缩放按钮。
- 场景加载失败清理事件和超时，避免重复执行模块；提供可点击的重新载入按钮，提示不会被悬停覆盖。
- Vercel 使用 `npm run build` 产生的 `dist`，访问计数转发至现有 Cloudflare Worker；排除本地缓存和预览文件。

## 检查结果

- 82 项 Node 测试通过，包含新增的模块失败处理检查。
- 静态构建、Cloudflare 发布 dry-run、Git diff 格式检查通过。
- 构建内 HTML、CSS、JS 的字面量素材引用没有缺失。
- Chromium：四个首页入口、返回全景、行走、缩放、夜景、时雨、酒楼真实点击入店、两种席位、选菜、上菜通过。
- 触屏模拟：320 × 568、390 × 844、768 × 1024、844 × 390，首页、街市、灯会无页面横向溢出，主要控制按钮在视口内；390 × 844 点选首尾菜品并上菜通过。
- 完整交互：键盘行走、暂停冻结、声音开关、虹桥接绳牵引、过桥完成、画稿打开、招船、渡河下船通过；无脚本异常或资源失败。
- 网络：禁用缓存、80 ms 延迟、下载 10 Mbps，首页至茶市可交互约 10.2 秒；主动阻断场景模块后，真实点击重新载入可恢复进入。
- WebKit 26.6：移动端首页、WebGL 水面、灯会、昼夜切换、食单、备餐、上菜与回到酒楼外通过。320 × 568 与 844 × 390 食单无页面横向溢出，备餐按钮在视口内。后台切换曾触发 WebGL context lost/restored，页面已恢复。

## 性能采样

每场景使用 requestAnimationFrame 采样 2.5–3 秒。Chromium、桌面 1440 × 900 的四街区、行走、放大、昼夜及下雨约 119.7–120 FPS。触屏模拟 DPR 2：三个竖屏尺寸的城门和舞台约 120 FPS；844 × 390 横屏舞台约 72.3 FPS（P95 帧间隔 18.3 ms）；手机酒楼约 120 FPS。未降低素材分辨率或人物数量。

原始脚本、截图和测量数据在本地 `output/playwright/release-*`，不进入发布包。
